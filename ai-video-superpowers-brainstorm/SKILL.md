# AI Video Superpowers · brainstorm

套件第一阶段：把用户模糊的视频想法，通过访谈变成一份可审核的 `spec.md`（场景片段/人物/场景/台词/参考素材）。**不生成视频**；产出 spec 后提示用户下一步用 `ai-video-superpowers-spec-to-plan`。

**核心概念区分（勿混淆）**：
- **场景片段**：故事的一个叙事单元（一场戏），含剧情、时长、台词、出场人物、环境。spec 的主体。
- **分镜/机位/景别/镜头运动**：执行层概念，属于 spec-to-plan 的 plan.md，**本阶段不产出、不写入 spec**。
- **画面风格**：视觉呈现类型（写实 / 动漫 / 3D / 水墨 / 赛博…），全局统一，决定生图/生视频提示词里的风格关键词。
- **氛围风格**：情绪与光线色调（阴郁悬疑 / 温馨明亮 / 热血燃 / 冷峻科技感…），可按场景变化，与画面风格是两个维度，**不要混为一谈**。

## 项目约定（三技能共用，勿偏离）

项目根目录：`/var/minis/shared/ai-video/<slug>/`（shared 跨会话持久；用户指定路径则以其为准；slug 用小写英文/拼音）。

```
<project>/
├── spec.md      # 本技能产出：场景片段级脚本
├── plan.md      # spec-to-plan 产出（分镜/SEG/提示词在这里）
├── refs/        # 已审核通过的参考图（人物三视图/场景六宫格六视图/风格）

├── clips/       # 视频片段 SEG-01.mp4 ...
└── output/      # 成片 final.mp4
```

若项目里已有 `spec.md`，先问用户是重新策划还是在其基础上迭代（迭代则先读入）。

## 访谈流程

1. **先问最关键的**：视频用途/投放平台、目标时长、画幅比例。用户已提到的信息不要重复问。
2. **一次只问一个问题**，等用户回答后再问下一个；问题按重要性排序，收齐核心信息再进入后续话题。
3. 每个问题给出 2~4 个**推荐选项 + "自定义"**（用户可直接描述），选项用数字编号（1. / 2. / 3. …），**用户可以直接回复数字**选择。
4. 逐个覆盖（顺序即优先级）：
   - **画面风格**：明确问"视觉呈现用哪种风格？"，推荐选项：1. 写实（电影感实拍质感）2. 动漫/2D 动画 3. 3D 动画（皮克斯式）4. 水墨/国风 + 自定义。用户选定后，**再单独问氛围风格**（阴郁悬疑/温馨治愈/热血燃/冷峻科技感…，可逐场景不同）——两者分开问、分开记录，勿合并成一个问题。
   - 主要人物（数量、身份、外貌形象细节：年龄/发型/服装/气质）
   - 场景（地点、时代、时间光线，要具体）
   - 剧情梗概与节奏、台词/旁白/字幕
   - 配乐音效偏好、分辨率质量（768P 试稿 / 1080P+ 成品）
5. 某项用户说"都行"时，**替他定一个默认值并说明理由**，不要僵持。
6. **文字信息收齐后**：整理素材清单（人物/场景/物品/风格图），进入下方「参考素材收集环节」逐项单独提问，全部处理完（落盘或标"待补"）才开始写 spec。

## 参考素材收集环节（人物、场景、物品、风格）

**文字信息收齐后、写 spec 之前，必须逐项单独提问收集参考素材**（这是访谈的最后一批问题）：

1. 先从已收集的文字信息整理出**素材清单**：每个出场人物、每个场景/环境、每个关键物品（全局风格图可选）。在 chat 里列出来让用户过目。
2. 然后**逐项单独提问**，一项一题、等用户回答后再问下一项，问题格式固定：

   > 「<设定名>」（<一句话说明，如：主角，35 岁考古队长>）的参考图素材怎么来？
   > 1. 自动生成（我按规则写提示词生成，生成后给你审核）
   > 2. 上传已有素材（你直接发图给我）

   用户可直接回复数字。某项用户说"跳过/都行"时按"暂缺待补"处理（见第 4 条），不要僵持。

3. 按用户的选择处理：
   - **选 2（上传已有素材）**：请用户直接发图（可多张）。图会落在 `/var/minis/attachments/`，复制进项目 `refs/` 并命名（如 `refs/char-lin.png`、`refs/scene-alley.png`）。上传图**不强制**符合下方三视图/六宫格格式（自有素材优先按原样用），但若明显不利（如人物只有单角度单张、背景杂乱），要提醒用户可能影响后续一致性，并记录到 spec 待确认项。
   - **选 1（自动生成）**：按下方各类型规则写提示词，调用：
   ```sh
   python3 /var/minis/skills/zhike-image/scripts/image.py submit \
     --prompt "..." --ar 16:9 --res 1K --version flare
   # → task_id；再 poll --task-id <ID> --timeout 600，最后 download 到 refs/
   ```
   （协议细节先读 `/var/minis/skills/zhike-image/SKILL.md`；图片 key 用 `/var/minis/shared/zhike/image.key`。）
4. **展示审核**：`![参考图](minis://attachments/xxx.png)`（或项目内路径的预览链接）给用户，**通过才落盘到 `refs/`**，不通过按反馈改提示词重生成（最多 2~3 轮，仍不满意则记录到 spec 待确认项）。上传的素材也请用户过目确认落盘文件名。
5. 暂缺参考图的设定照常写进 spec，标注"待补"（后续子智能体初审会兜底检查）。

**人物参考图 = 无头全身三视图 + 正脸特写（自动生成时必须遵守）**：
为保证跨片段人物一致性且避免身体/面部互相干扰（视频模型参考人物图时，全身像的脸常与正脸打架），人物参考图用**一张横版 2K 纯白背景图**：左侧无头全身三视图（正/侧/背并排，颈部以上干净移除，服装道具一致），右侧同一角色正脸特写。**提示词模板、图面规格、实战范例详见 `references/char-ref-prompt.md`**（生成前必读）。调用：`--ar 16:9 --res 2K`。

**场景/环境参考图 = 单张六宫格多视图（自动生成时必须遵守）**：
环境参考图生成**一张图内的 3×2 六宫格组合**，六个格子固定为同一场景的六个视图（场景元素在各视图中保持一致）：
1. 俯视 45° 全景图（斜上方俯瞰，全场景布局一览）
2. 90° 垂直俯视图（正上方顶视平面，地面/陈设布局）
3. 正视图（正面平视）
4. 反视图（背面平视）
5. 左视图（左侧平视）
6. 右视图（右侧平视）

提示词写法（套用）：「同一场景的六视图组合图，3×2 网格排列，六个格子依次为：<场景描述>的 ①45°俯视全景 ②90°垂直俯视顶视图 ③正视图 ④反视图 ⑤左视图 ⑥右视图；场景元素（<列出关键物件>）在所有视图中位置与样式保持一致，各格纯场景无人物无文字标注，<画面风格 + 氛围光线描述>」。调用：`--ar 16:9 --res 2K`。

场景描述要**具体**：地点+时代+时间光线+关键陈设物件（"1990 年代中国县城老诊所，下午斜阳，木桌、药柜、蓝白条纹帘、老式台灯"级别，不要只写"一个诊所"）。

**物品参考图**（剧情关键道具如信件、怀表、凶器）：单独生成白底单物特写图，多角度可选。

每个参考图在 spec 第 8 节参考素材中按顺序逐张展示（格式见上方「输出 spec.md」小节，路径 + 用途 + 内嵌图片，不用表格）。

## 输出 spec.md

读取模板 `/var/minis/skills/ai-video-superpowers-brainstorm/references/spec-template.md`，整合全部信息写入 `<project>/spec.md`：

- **主体是"场景片段"表**，每行一个场景片段：编号 SC-01…、片段名、主要剧情（这场戏发生了什么，具体到可改写成生视频提示词，但**不写机位/景别/镜头运动**）、大概时长、人物/旁白的**具体台词**（逐句写出，不要只写"两人对话"）、出场人物（列名，括注其参考图路径或"待补"）、环境场景（具体描述 + 参考图路径或"待补"）、涉及关键物品（有则注明 + 参考图）。
- **时长设计按语速核算（核心规则）**：
  - 中文对白约 3~3.5 字/秒、旁白约 3.5~4 字/秒（含自然停顿），每句另加 ~0.3s 句间停顿。
  - 每场 SC 时长 = 台词总秒数 + 动作/情绪呼吸余量（15~25%），**宁松勿密**。
  - 单个场景片段建议 5~20s；若一场戏"台词多 + 剧情重"算出来超过 20s，就**拆成两场戏**，不要硬压时长。
  - 各片段时长之和贴合目标时长；写 spec 时先逐句排台词，再倒推每场时长，避免"12 秒塞 60 字台词"式超载。
- 画面风格与氛围风格**分开两栏记录**（基本信息/风格章节）。
- **spec.md 保持纯文本（不内嵌任何图片）；用户审核走 spec.html**（Minis 自带 markdown 预览对长文档会崩溃——OpenMinis issue #413：解析器逐行循环编译正则 → VMA 耗尽 SIGABRT，2026-09-30 仍 open；且 app 崩溃重启可能从快照回退 shared 文件，重要节点建议同时把 spec 内容摘要进 chat 留底）。流程：
  1. 写好 spec.md（第 8 节为文字清单：`### N. 素材名` + `- 路径：\`refs/x.png\`　|　用途：…　|　类型：…`，不放图片）
  2. 用 ffmpeg 生成缩略图：`ffmpeg -y -i refs/x.png -vf scale=480:-1 refs/thumbs/x.jpg`
  3. 生成审核页：`python3 <skill>/scripts/make_spec_html.py --project /var/minis/shared/ai-video/<slug>` → 产出 `<project>/spec.html`（依赖 py3-markdown：`apk add py3-markdown`，装在 /usr/bin/python3.12，脚本自动 execv 切换）
  4. 给用户链接：`[spec 审核页](minis://shared/ai-video/<slug>/spec.html)`；skill/子智能体始终读 spec.md
- **spec.html 排版规则（脚本自动完成，无需手工干预）**：
  - ≥3 列表格 → 行卡片（每行一卡：标题=首列，字段竖排，标签列 minmax(84px,26%) 自适应均衡、值超长换行）
  - 2 列表格 → 均衡键值卡（约 3:7 分栏，值换行）
  - 单元格/字段中的 `refs/*.png` 路径自动替换为可点击缩略图（132px，点击弹出 lightbox 看原图，＋=×1.3 / －=×0.77 乘法缩放，懒加载）
  - 第 8 节 → 素材缩略图卡片网格（同 lightbox 放大）
- 人物表/场景表/物品表中的参考图列保持纯文本路径（渲染时脚本自动转缩略图）。
- 写完后给用户**简要摘要**（不是全文粘贴）。

## spec 双审（子智能体，必须执行）

spec.md 落盘后，**派出子智能体**（subagent_task，General Sub Agent）做两项独立审核。审核任务书模板见 `/var/minis/shared/ai-video-sp-skills/ai-video-superpowers-spec-to-plan/references/audit-prompt.md`（A 段 = spec 时长审核；跨 skill 共用文件）。**子智能体只读不改，所有修改由本智能体执行。**

### 审 1：参考图完备性初审

任务书要点（写给子智能体）：读取 `<project>/spec.md`（第 8 节参考素材的路径行与各表引用）、与 `<project>/refs/` 目录实际文件，逐项核对 spec 中出现的**所有人物、场景/环境、关键物品**：是否已有参考图（spec 第 8 节登记 + refs/ 文件真实存在，两者都要查）；人物图是否满足"无头全身三视图 + 正脸特写、纯白背景"要求；场景图是否为"单张六宫格六视图（45°俯视全景/90°垂直俯视/正/反/左/右）"。返回结构化清单：✅ 已有且合规 / ⚠️ 有图但不合规（如人物图带背景、场景不是六宫格规格）/ ❌ 缺失（列出是哪个角色/场景/物品，在哪个 SC 片段被引用）。

拿到初审结果后：
- 若**无缺失且合规**：告知用户初审通过，直接进入审核环节。
- 若**有缺失/不合规**：把清单整理成可读列表展示给用户，**提示补充**——每个缺失项问用户"上传 / 授权自动生成（人物按三视图规则、场景按六宫格六视图规则）/ 暂缺待补"。补齐后更新 spec 第 8 节参考素材，可再跑一轮初审确认。

### 审 2：时长设计审核（循环直到通过）

按 audit-prompt.md A 段任务书派审：逐场 SC 核算台词秒数（对白 3~3.5 字/秒、旁白 3.5~4 字/秒，含停顿）与最低动作时长，对比标注时长——塞不下 = 太密；内容低于时长需求一半 = 太稀疏；各场之和 vs 目标时长。

- 返回"不通过"→ 按其清单**修改 spec.md**（加时长 / 删减台词 / 拆场 / 合并场）→ **再派审核，循环直到通过**（上限 3 轮，仍不过则把分歧点列给用户裁决）。
- 通过后把审核轮次与结论写进 spec.md 第 9 节"初审与时长审核记录"。
- 向用户汇报时附上时长审核结论摘要（逐场台词秒数 vs 标注时长）。

## 审核与移交

给用户 spec 摘要 + 双审结果（参考图初审 + 时长审核结论），明确请其审核（**看 spec.html 审核页**，文字源头是 spec.md）；用户改完确认后，把 spec.md 头部状态行改为"已审核"，并提示下一步运行 `ai-video-superpowers-spec-to-plan`。
