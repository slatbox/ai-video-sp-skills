# 时长设计审核 · 子智能体任务书模板

供两个阶段共用，派 subagent_task（General Sub Agent）时把对应段全文写进 task（替换方括号，附上文件绝对路径）。子智能体只读文件、只做核算与判断，**不修改任何文件**；返回结构化结论文本。

## 核算基准（两个审核共用）

- **中文语速**：对白 3~3.5 字/秒；旁白 3.5~4 字/秒；数字/外文/拗口词按 2.5 字/秒。每句另加 ~0.3s 句间停顿；情绪重读句 ×1.3。
- **动作/镜头时长**：每个分镜定格 1.5~3s（动作格 1.5~2s，氛围/表情/空镜/转场格 2~3s）。
- **合格线**：台词总秒数 + 动作呼吸余量（15~25%）≤ 段时长，且不低于段时长的 50%（低于 = 太稀疏）。
- 硬限制：单段 4~15s。

## A. spec 时长审核任务书（brainstorm 阶段用）

```text
你是视频策划审核员。请审核一份 AI 视频 spec 的时长设计是否合理。

读取：
1. spec：<spec.md 绝对路径>
2. 参考素材目录：refs/（只需知道有哪些图，不必审图）

逐场戏（SC）核算：
1. 把该 SC 的"台词/旁白"逐句抄出，按语速基准估算每句秒数，累加得台词总秒数。
2. 估算该 SC 剧情需要的最少分镜数（每个叙事节拍 1 格，1.5~3s/格），得动作最低秒数。
3. 对比 SC 标注时长：台词+动作塞不下 → 该场"太密"（超载）；低于内容最低需求 1.5 倍以上的空转 → "太稀疏"。
4. 检查各 SC 时长之和是否等于目标时长；单场是否在 5~20s 区间。
5. 检查剧情量与时长是否匹配：一场戏要求"大段对白+复杂动作"却只给几秒 = 明显不合理。

输出（纯文本）：
- 总判定：通过 / 不通过
- 逐场清单：SC-xx｜标注 xs｜台词约 ys（N 句）｜预计最少需 zs｜判定 ✅ / ⚠️太密 / ⚠️太稀 / ❌严重失配
- 不通过时：每个问题给具体修改建议（加时长 / 减台词 / 拆场 / 合并场），并给出建议时长值。
```

## B. plan 时长审核任务书（spec-to-plan 阶段用）

```text
你是视频执行方案审核员。请审核一份 AI 视频 plan 的时长与分镜设计是否合理。

读取：
1. spec：<spec.md 绝对路径>（内容源头：剧情、台词、人物、环境）
2. plan：<plan.md 绝对路径>（SEG 切分、时长、分镜 P01–Pxx、prompt）

逐段（SEG）核算：
1. 台词核算：从该 SEG 的 prompt/分镜节点里找出所有台词，逐句按语速基准（对白 3~3.5 字/秒、旁白 3.5~4 字/秒、句间停顿 0.3s）估算总秒数，对比段时长。塞不下 → ❌ 台词超载；对照 spec 核对台词是否被无故删改。
2. 分镜密度：数该段分镜格数 N，段时长/N = 平均格时长。>3.5s/格 且无慢节奏设计理由 → ⚠️ 太稀疏（拖沓/空转）；<1.2s/格，或一格同时塞多个不兼容动作、两句长台词 → ⚠️ 太密（观众看不完）。合理区间 1.5~3s/格。
3. 段间节奏：连续多段全部顶满 15s 但每段内容单薄 = 稀释注水；大量 4~6s 短段碎切 = 零碎。检查切点是否切断进行中的对话/动作。
4. 与 spec 一致性：SEG 是否完整覆盖所有 SC 的剧情与台词，无遗漏、无擅自新增剧情；连贯/独立判定与 spec 的衔接描述一致。

输出（纯文本）：
- 总判定：通过 / 不通过
- 逐段清单：SEG-xx｜xs｜N 格｜平均格时长｜台词约 ys｜判定 ✅ / ⚠️ / ❌ + 一句话理由
- 不通过时：每个问题给具体修改建议（改时长 / 增删分镜 / 重新切分 / 删改台词），并给出建议值。
```

## 审核循环规则（两个阶段共用）

- 返回"不通过"→ 主智能体按清单修改 spec.md / plan.md → 再次派审 → 循环直到通过，**上限 3 轮**；3 轮仍不过，把剩余分歧点整理给用户裁决。
- 通过后：把审核轮次与结论写进文档对应"审核记录"栏（spec 第 9 节 / plan 末尾审核记录行）。
- 子智能体只核算不改文件，所有修改由主智能体执行，保持格式合规。
